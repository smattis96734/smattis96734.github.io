--- layout: essay title: "My Experience with TypeScript and Athletic Software Engineering" date: 2026-09-10 --- As a student who has gone into a few programming classes about specific programming languages I found it intimidating to learn javascript and typescript at the same time. Only to find out that typescript is really just an extension of javascript and hold the same principles as each other. While learning typescript a lot of key concepts from my previous programming classes really helped me simply know how to work with typescript. Concepts such as making variables, loops, methods, and classes just needed to be translated into typescript code. Making this transition into typescript a lot smoother than I initially thought. However, learning typescript came with its own challenges. Particularly learning ES6. ES6 was a whole new approach to programming I have never seen before. At first I was rather irritated learning ES6 because the arrow functions were not something I was familiar with. Additionally, when the arrow functions were used it made it more difficult to read the code. Although ES6 was frustrating there were some aspects I appreciate. Aspects such as Maps and Sets, Enhanced Object Literals, Block Scoping, Classes and Inheritance. While learning typescript my class did a lot of assignments based around the idea of doing athletic software engineering. This approach focused on aspects like repetition and speed. If you are familiar with crossfit you might be aware of the term “workout of the day” (WOD). This idea was incorporated into my software engineering class by creating timed assignments about 3-4 times a week. The clock is what made it most stressful but if you could create loops, methods, and classes with typescript the assignment would be relatively easy. I believe that the repetition really helped drive me to be an overall better programmer and made challenging programming assignments seem easier. Overall, learning TypeScript and adapting to ES6 taught me that programming languages may look different on the surface, but they share the same logical foundation. Once I understood that, I could focus more on problem solving than syntax. The athletic software engineering approach pushed me to think faster and code more efficiently, and although it was stressful at times, it helped me build confidence in my skills.
